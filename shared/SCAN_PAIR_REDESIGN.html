扫码配对界面改版

现状：点「扫码配对」后是一块 260dp 的深色方块，里面一个二维码图标，按「打开相机扫码」又跳到 ZXing 的全屏横屏扫描页。
改版目标：把相机放回页面里、保持竖屏、让取景框自己说明用法，扫到码后不再突然弹窗，改成底部确认卡。

1现在到底哪里别扭

三个问题叠加，才让人看不懂那块黑框。改版要同时解决，只换皮没用。

黑框无意义 它只是个占位图，不是相机

深色 Box + 76dp 的 QrCodeScanner 图标，既不预览也不响应，看起来像"坏了"。真正的扫描发生在另一个 Activity 里。

横屏跳转 ZXing 默认锁横屏

ScanOptions.setOrientationLocked(false) 仍沿用 CaptureActivity 的 sensorLandscape。竖屏 App 里突然横过来，还要单手举着扫。

交互断层 扫码 → 全屏 → 弹窗 → 回页

四次视觉切换，每次都要重新找焦点；扫错码只有一个 Toast，没有留在页面里的解释。

左侧是改动很小的「出示二维码」页（保持对照），中间是全新的扫描页，右侧是扫码成功后的确认卡。

4交互与规则

状态机

状态触发表现
Scanning进入扫码 Tab / 取消确认取景框白色四角 + 扫描线循环
Found解出 FG_QR暂停解码，底部卡片升起 220ms
Pairing点「确认连接」按钮 loading，卡片锁定，15s 超时
Success收到 HELLO_ACK|OK绿勾 1.2s 后自动返回
Error非配对码 / 拒绝 / 超时框闪红 + 提示条，可重扫

关键规则

  • 竖屏优先：扫码页固定竖屏；横屏时改为左右分栏（左预览、右说明），不再锁死横屏。
  • 只扫一次：识别成功立刻停解码，避免同一码连发多次 FG_HELLO。
  • 不自动跳转：扫码成功不会自动发文件、不会自动配对，必须人点确认。
  • 页面离开即停相机：切到出示二维码 Tab 或返回时释放 CameraX/ZXing 资源，不让相机在后台常开。
  • 与出示页互斥：同一时刻只有一侧占用相机与配对 token。
  • 无障碍：取景框带 contentDescription「扫描二维码取景框」；扫描线动画可被系统"减少动态效果"关闭；所有按钮 ≥ 48dp。
为什么不再用独立扫描 Activity：跳出页面会丢掉"我在添加设备"的上下文，而且 ZXing CaptureActivity 的横屏、系统样式、返回栈都改不动。 改成页内 DecoratedBarcodeView（journeyapps 自带，无需新增依赖）+ Compose AndroidView 嵌入，取景框、手电筒、相册都能自己控制。

5实现落点（已实现 · v2.4）

文件改动
MainActivity.kt · PairScreen扫码 Tab 由「黑框 + 按钮」改为 AndroidView { DecoratedBarcodeView }；自定义 ViewfinderView 画四角与扫描线；解码回调里只取第一次结果。
MainActivity.kt · 确认层AlertDialog 改为 ModalBottomSheet；pairing 状态驱动 loading 与 15s 超时；成功后绿勾延时返回。
新增 ScannerView.kt封装相机视图：生命周期绑定、手电筒开关、相册识别（RGBLuminanceSource）、权限拒绝态。
AndroidManifest.xmlMainActivity 加 configChanges 由 Compose 自行处理旋转；不再依赖 CaptureActivity 的横屏声明。
依赖不新增：zxing-android-embedded 4.3.0 已含 DecoratedBarcodeView 与 BarcodeCallback。

工作量集中在扫描页本身，配对协议（FG_QR / FG_HELLO）与 token 规则一行未改。v2.4 已按此实现：compileDebugKotlin 通过，正式包 数据线.apk 已签名。
