# 飞鸽 P2P 通信协议 v1.0

两端（PC / Android）必须严格遵守本协议，否则无法互通。协议刻意设计得极简，只用标准 socket，不加密、不压缩、无依赖。

## 1. 网络模型

- 每台设备同时扮演两个角色：
  - **发现端**：通过 UDP 广播宣告自己 + 监听他人的广播
  - **传输端**：开一个 TCP 监听端口，接受别人发来的文件；同时能作为客户端连接别人的 TCP 端口发文件
- 无中心服务器，纯对等（P2P）
- 默认端口：UDP `2425`（发现），TCP `2425`（传输）。两端可配置但必须一致。

## 2. 设备发现（UDP 广播）

### 广播包格式（UTF-8 文本，单行，以 `\n` 结尾）

```
FG_P2P|1|<name_b64>|<ip>|<tcp_port>
```

| 字段 | 说明 |
|------|------|
| `FG_P2P` | 魔数，固定值，用于过滤无关 UDP 包 |
| `1` | 协议版本号 |
| `<name_b64>` | 设备名，UTF-8 字节再 Base64 编码（避免分隔符和中文问题） |
| `<ip>` | 发送方的局域网 IPv4 地址（点分十进制） |
| `<tcp_port>` | 发送方 TCP 监听端口 |

### 行为规则

- 启动后**每 2 秒**向 `255.255.255.255:2425` 广播一次自己的信息（同时监听 `0.0.0.0:2425` 的 UDP）。
- 收到广播包：解析字段，校验魔数和版本；若 `ip` 不是自己，则以 `<ip>:<tcp_port>` 为唯一键加入/刷新设备列表，记录当前时间戳。
- **离线判定**：某设备超过 **6 秒**（3 个周期）没收到广播，从列表移除。
- **设备名变更**：名字随每个广播包携带，用户改名后**立即广播一次**普通包（带上新 name_b64），对方按 `<ip>:<tcp_port>` 键刷新其显示名即可，无需新增协议字段；改名同时本地持久化，重启后仍用新名。
- 退出时广播一次 bye 包（见下），让对方立刻移除自己：

```
FG_P2P|1|<name_b64>|<ip>|<tcp_port>|BYE
```

（比普通包多一个 `BYE` 尾字段；收到含 `BYE` 的包直接移除对应设备。）

## 3. 文件传输（TCP）

### 3.1 连接与握手

- 发送方作为 TCP 客户端，连接接收方 `<ip>:<tcp_port>`。
- 连接建立后，发送方**先发一个请求头**（UTF-8 文本，单行，`\n` 结尾）：

```
FG_FILE|1|<name_b64>|<size>|<filecount>\n
```

| 字段 | 说明 |
|------|------|
| `FG_FILE` | 魔数 |
| `1` | 版本 |
| `<name_b64>` | 文件名（含扩展名），UTF-8 → Base64 |
| `<size>` | 文件总字节数（十进制整数） |
| `<filecount>` | 本次发送的文件个数（本协议一处连接只发 1 个文件，固定为 1，预留扩展） |

### 3.2 接收方应答

接收方读取请求头后，回复（UTF-8 文本，单行，`\n` 结尾）：

- 同意并准备接收：`FG_ACK|1|OK\n`
- 拒绝（如空间不足/用户取消）：`FG_ACK|1|REJECT|<reason_b64>\n`

### 3.3 数据传输

- 发送方**收到 OK 后**才开始发送文件原始字节流（裸字节，不做任何编码）。
- 发送方按流式分块发送（如 64KB/块），不做整体内存加载，支持 1GB 以内文件。
- 接收方按 `<size>` 精确读取字节，写入到「接收目录 / 文件名」。
- 若目标文件已存在：自动改名为 `文件名 (1).扩展名`、`(2)` …，不覆盖。

### 3.4 完成确认

- 接收方写完 `<size>` 字节后，回复：`FG_DONE|1|<received_size>\n`
- 发送方读取 DONE，校验 `received_size == size`，一致则本次传输成功，关闭连接。

### 3.5 超时与中断

- 握手阶段（等 ACK）：10 秒超时，超时视为失败。
- 数据传输阶段：60 秒无数据进展视为失败。
- 任一方异常断开：另一方关闭连接、清理临时文件（接收方写入时用 `.part` 临时文件名，收齐后重命名，避免残留半截文件）。

## 4. 接收目录

- PC 端：程序目录下的 `received/`
- Android 端：公共 Download 目录下的 `飞鸽收件/`

## 5. 设计取舍说明

- 用 Base64 编码文件名：规避中文、空格、分隔符 `|` 带来的解析歧义。
- 一次连接只传一个文件：逻辑简单，失败重传粒度小；多文件可建立多个连接。
- 无加密：局域网可信环境，符合需求。
- 固定端口 + 广播发现：跨网段需手动填 IP 直连（发送方支持手动输入 IP 绕过发现）。
