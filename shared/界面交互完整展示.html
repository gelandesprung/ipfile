入口并列

C

载荷不同

D

防扫错
两页图标/色带不同，二维码下方固定一行小字说明扫码方类型。

关键交互流程与决策

所有流程都建立在"熟人面对面"前提上：不踢人、无文件池、仅浅色、默认简单。

三条主流程加入 → 收发 → 群发
1

开服务 → 加入
主界面点「🌐 网页模式」→ 服务启动、生成地址与 PIN → 朋友扫码/输地址打开 → 填昵称+PIN → 进入等待页，Host 访客列表出现。

2

定向发 / 上传
Host 长按访客发文件 → 访客确认卡接收；访客上传 → Host 复用原确认框 → 按平台落盘（PC 选位置 / 安卓默认）。

3

群发
Host 点群发 → 勾选多人 + 选文件 → 逐人 offer、各自确认、独立传输，互不影响。

4

地址族切换
点 IPv4/IPv6 → 地址与二维码联动更新；PIN 不变、在线访客不掉线，只影响新扫码者。

9 项已确认决策本设计稿定稿依据
1 不踢人：刷新 PIN 不影响在线访客
2 不要文件池、无中转：上传直接落盘（PC 选位置 / 安卓默认）
3 访客不改名字：加入时填一次，之后只读
4 需要群发入口：多选访客逐人发送
5 仅浅色，不做深色切换
6 端口每次启动随机（20000–61000），可点「换端口」重随机
7 网页面默认 IPv4，配对码维持 IPv6 优先
8 地址族切换不联动已连接访客
9 配对码不加地址族切换（保护已测流程）
